# OpenAI 兼容图像

## 能力与请求

- 配置支持 `POST /images/generations` 的服务基址、图像模型和访问密钥。适配器用 Bearer 鉴权，传入 `model`、`prompt`、`n: 1` 和 `size`。当前入口是文生图，使用 `data[0].b64_json` 或 `data[0].url` 获取一张图。
- 横屏、竖屏和方图分别请求 `1536x1024`、`1024x1536` 和 `1024x1024`。服务必须支持这组尺寸或兼容处理一次请求。当前入口不上传参考图。需要锁定同一角色的脸和发型时，选能实际传图的已配置模型。
- 凭据随命令注入。扩展脚本写到指定输出路径，避免打印密钥、完整响应或本地文件路径。

## 如何生成

- 角色图用 `{"commands":[{"skill":"openai-image","cardId":"actor-01","outfitId":"ceremony"}]}`。缺省服饰 ID 时生成默认服饰。对同一套服饰，提示词描述统一脸、体型、发型和服装，只出一幅五视图图页。五格为正面上身、正面全身、面部特写、左侧、右侧。纯净空白底，无额外人物、道具、布景或文字。
- 场景图绑定场景卡时写布局、空间关系、时间、光线和辨识地标，保留无人物的干净环境。道具图交代轮廓、材料、纹理与尺寸比例，采用干净中性背景。分镜底图用 `shotId`，画面从该镜脚本取，用同镜定稿的主体。避免把五视图版式带进分镜图。
- 成功后核对图片实际绑定到所选服饰或分镜底图。有定稿时复用；明确重做时可使用 `regenerate: true`。

## 走一遍可复现的生图任务

1. 在「模型配置 → 图像生成」选「OpenAI 兼容生图」，填写 API 基础地址、接入方提供的模型名和 API Key。基础地址应包含该服务的 API 前缀，入口会追加 `/images/generations`。
2. 从「角色与设定」选中角色服饰后点「生成五视图」，或从分镜工作台点「生成分镜参考图」。有同名角色时，以工程 ID 和选中的服饰 ID 为准。
3. 使用助手时先读 `read_project(section=cards)` 或 `read_project(section=shots)`。下面是三种命令目标。使用当前工程的真实 ID 替换示例。

```json
{
  "commands": [
    { "skill": "openai-image", "cardId": "role-lan", "outfitId": "raincoat" },
    { "skill": "openai-image", "cardId": "scene-pier" },
    { "skill": "openai-image", "shotId": "shot-03" }
  ]
}
```

4. 提交的 `prompt` 由目标类型组装，设定图和分镜底图各自独立。图像请求可携带 `prompt` 补充可见细节。检查结果回执里的 `assetId` 以及绑定目标。用于统一人物身份的图建议先人工检查再进入视频生成。

| 现象             | 处理                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------- |
| HTTP 404         | 核对所填 API 基础地址和模型是不是同一个接入方的图像端点，确认路径末尾没有重复填写图像方法名。 |
| HTTP 400         | 检查模型是否接受这套尺寸和兼容格式。根据回复调整模型或服务配置。                              |
| HTTP 401/403     | 确认密钥对应当前地址并有图像权限。                                                            |
| 收到返回但没有图 | 验证服务能提供 `data[0].b64_json` 或 `data[0].url`，URL 的可访问性和有效期也会影响入库。      |
| 换衣后脸不一致   | 当前入口只提交文本。切到支持图像条件的千问图像 3.0 接口或手工导入同一角色的定稿。             |
